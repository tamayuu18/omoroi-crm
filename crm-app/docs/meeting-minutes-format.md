# 議事録フォーマット（Notta自動連携）

Notta連携（`/api/cron/notta`）が対応履歴に書き込む議事録の仕様です。
AIへの指示はこの仕様と同じ内容を `src/lib/minutesFormat.ts` に持っています。
見出しを変えるときは両方を合わせて更新してください。

## 経緯：議事録が要約されすぎていた原因

2026-07-31 の変更（コミット `e05f496`）から、Nottaが Google ドキュメントに書き出す
「AI要約」セクションがある場合は、**その要約をそのまま議事録本文として保存**していました。
AI生成は氏名・連絡先・次回アクションの抽出にしか使われず、議事録本文には関与していません。

Nottaの要約は数行の概要とアクションアイテムだけなので、対応履歴に残る議事録も
その粒度になっていました。これが「要約されすぎ」の直接の原因です。

さらに、要約が無いドキュメント（文字起こしのみ）に対するAI生成も、
プロンプトが「簡潔で実務に使える議事録」「## 要約 / ## 決定事項 / ## ToDo / ## 懸念・特記」
という指示だけで、分量や残すべき情報の指定が無かったため、短くなりがちでした。

## 現在の動作

- 文字起こしがあるドキュメントは、**文字起こし全文**から下記フォーマットの詳細議事録をAIで生成します。
  Nottaの要約は「話題の抜け漏れチェックの参考」としてAIに渡すだけで、本文には使いません。
- 文字起こしが無く要約だけのドキュメントは、要約の情報を落とさずに同じフォーマットへ整形し、
  末尾に「文字起こしが無いため要約をもとに作成」の注記を付けます。
- `ANTHROPIC_API_KEY` が未設定のときは、従来どおり本文を整形せず `## 面談メモ（自動整形なし）` として記録します。

## フォーマット

```markdown
## 面談概要
- 面談日時:
- 面談種別: 初回面談 / 2回目以降 / 状況確認 / 面接対策 / 内定後フォロー / その他
- 参加者: CA ○○ ／ 求職者 ○○様
- 所要時間:

## 求職者の現状
- 現職・経歴（会社名、職種、在籍年数、担当業務、現年収）
- 転職理由・きっかけ（本人の言葉に近い形で、背景まで）
- 転職活動の状況（他エージェントの利用、応募中・選考中の企業、内定の有無）

## 希望条件
- 職種・業界
- 勤務地・働き方（リモート可否、残業、転勤、勤務時間）
- 年収（現在 / 最低ライン / 希望）
- 入社可能時期
- 譲れない条件と優先順位
- 避けたい条件

## 面談内容（詳細）
### （話題ごとに小見出し）
- 話した内容を時系列で、具体的に（数字・固有名詞・理由・背景を省略しない）
- 求職者の発言は「求職者:」、CAの説明や提案は「CA:」と区別する

## 紹介・提案した求人／企業
- 企業名・ポジション・求職者の反応（興味あり / 保留 / 辞退）とその理由

## 決定事項・合意事項

## ToDo
### CA側
- [ ] 内容（期限: YYYY-MM-DD）
### 求職者側
- [ ] 内容（期限: YYYY-MM-DD）

## 懸念・特記事項
- 懸念点、配慮が必要な事情（家庭・健康・退職交渉の状況など）、温度感

## 次回予定
- 次回の面談・連絡の予定（日時・方法・内容）
```

## 書き方のルール（AIにも同じ内容を指示しています）

1. 「要約」ではなく「記録」。面談に同席していない人が読んでも、話の流れと中身を再現できる詳しさで書く。
2. 分量の目安は面談1時間あたり 2,000〜4,000字。1,000字を下回る場合は情報を落としていないか見直す。
3. 数字（年収、年齢、年数、件数、日付、時間）、固有名詞（企業名、職種、資格、ツール名、人名）、理由・背景は必ず残す。
4. 箇条書きは1項目1事実。「〜について話した」のような中身のない表現は使わず、何をどう話したかを書く。
5. 推測で補わない。本文に無いことは書かない。不明な点は「（不明）」と書く。
6. 該当が無い見出しは「特になし」と書き、見出し自体は削除しない。見出しの名称と順番は雛形どおり。
7. 話者は「求職者」「CA」で区別する。
8. 文体は常体（〜した、〜とのこと）。求職者には「様」を付ける。

## 対応履歴の各項目への反映

| 履歴の項目 | 内容 |
| --- | --- |
| content（本文） | 上記フォーマットの議事録。末尾に `<!-- #src:<fileId> -->` の重複防止マーカー |
| result（対応結果） | 面談結果の1〜2文サマリ（AI抽出） |
| nextContent（次回予定） | 次回アクション（AI抽出） |
| nextDeadline（次回期日） | 次回期日（AI抽出、あれば） |

## 過去の議事録を新フォーマットで作り直す

以前の実行で要約のまま保存された履歴は、`rewrite` モードで作り直せます。
本文が `## 面談概要` で始まる履歴（＝新フォーマット）は対象外なので、何度実行しても二重に作り直しません。

```
# 対象の一覧だけ確認（書き込みなし）
GET /api/cron/notta?key=<CRON_SECRET>&rewrite=dry

# 2026-09-01 以降の面談だけを作り直す
GET /api/cron/notta?key=<CRON_SECRET>&rewrite=1&since=2026-09-01

# 全件を作り直す
GET /api/cron/notta?key=<CRON_SECRET>&rewrite=1
```

1件ごとにAI生成が走るため（1件あたり1分前後）、実行時間の上限で途中終了したら
`status: rewrite-partial` が返ります。そのまま再実行すると続きから処理します。
新しい面談から順に処理するので、直近の履歴が先に直ります。

## 環境変数

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | （必須） | 未設定だと整形なしで記録 |
| `ANTHROPIC_MODEL` | `claude-sonnet-5` | 議事録生成に使うモデル |
| `MINUTES_MAX_INPUT_CHARS` | `150000` | AIに渡す文字起こしの上限文字数（超えた分は先頭のみ使用） |
| `MINUTES_MAX_OUTPUT_TOKENS` | `8000` | 議事録本文の出力上限トークン |
| `CRON_TIME_BUDGET_MS` | `240000` | 1回の実行で使う時間。残り90秒を切ると次の面談には着手しない |

## 運用上の注意

- 1回の cron 実行で処理できるのは数件（1件1分前後）です。面談が多い日は `status: partial` になり、
  翌日の実行で続きを処理します。溜まる場合は `GET /api/cron/notta?key=<CRON_SECRET>` を手動で呼ぶか、
  `vercel.json` の実行回数を増やしてください。
- 生成された議事録は対応履歴の「続きを見る」で全文を確認できます。
