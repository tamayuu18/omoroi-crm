## 1. システム概要

おもろいCRMは、キャリアアドバイザー（CA）の顧客対応・面談・求人提案・タスクを一元管理するための業務支援システムです。

主な管理対象:

- **顧客（求職者）情報** … 連絡先、現職・希望条件、対応ステータス、ヨミ（受注確度）
- **タスク** … 顧客ごとのやるべきこと・期限
- **面談** … 面談予約・実施状況（TimeRexと自動連携）
- **求人** … 提案先の求人情報（手動登録／自動取込）
- **求人提案** … 顧客と求人の組み合わせごとの選考状況（応募〜内定〜承諾）
- **KPI／ダッシュボード** … CAごとの活動実績・売上ヨミの可視化

以前はGoogleスプレッドシート＋Google Apps Scriptで運用していましたが、現在は本システム（Next.js + PostgreSQL、Vercelでホスティング）に完全移行しています。リポジトリ直下に残っている `.gs` ファイル群は旧システムの名残であり、CAの日常業務では使用しません。

## 2. ログイン方法

- ログインは **Googleアカウントのみ** 対応しています（ID・パスワード方式はありません）。
- トップ画面（`/auth/signin`）で「Googleでログイン」ボタンを押し、許可されたGoogleアカウントでサインインしてください。
- 利用できるアカウントは管理者が環境変数で許可リスト登録している場合があります。ログインできない場合（`AccessDenied` エラー）は管理者に確認してください。
- ログイン後は画面上部のナビゲーションにログイン中のユーザー名が表示されます。ログアウトは同じ場所の「ログアウト」ボタンから行います。
- 現状、CAごとのアクセス権限の違いはありません。ログインできれば全顧客・全求人・全タスクを閲覧／編集できます（担当CAの絞り込みはあくまで表示上のフィルタです）。

## 4. 顧客一覧画面（`/customers`）

### 表示項目
氏名／フリガナ、ステータスバッジ、タスクありバッジ、担当CA、送客日、初回面談日、次回アクション、次回期限（期限超過は赤字表示）、ヨミバッジ。

### 検索・絞り込み
- フリーワード検索（氏名／メール／電話番号）
- ステータス（23種類から選択）
- 担当CA
- ヨミランク（S/A/B/C/D）

条件はURLのクエリパラメータに保存されるため、検索結果をそのままURLで共有・再現できます。

### 並び替え
氏名／ステータス／送客日／初回面談日／次回期限の各列でクリックによる昇順・降順ソートが可能です。

### 次回アクションの完了操作
一覧上の「次回アクション」欄から、そのまま「完了」ボタンを押すと次回アクション／次回期限がクリアされ、対応履歴に自動で記録されます。

### 一括操作
チェックボックスで複数選択後、以下が可能です。
- 一括ステータス変更
- 一括削除（確認ダイアログあり）

### 新規登録
「新規登録」ボタンからモーダルを開き、以下を入力して顧客を新規登録できます。
氏名（必須）、フリガナ、電話番号、メール、担当CA、流入元、性別、居住地、現職企業／職種／年収、希望職種／勤務地／年収、転職希望時期、受注予定月、備考。

### CSVインポート
「CSVインポート」ボタンから顧客データを一括登録できます（詳細は「13. CSVインポート」参照）。

## 5. 顧客詳細画面（`/customers/[id]`）

### ヘッダー
- 顔写真（クリックでアップロード、2MB以下の画像）
- 氏名／フリガナ
- ステータスバッジ、ヨミバッジ、担当CA表示

### 主要アクションボタン
| ボタン | 内容 |
|---|---|
| ステータス変更 | 顧客ステータスを変更するモーダルを開く |
| ヨミ更新 | ヨミランク・受注予定売上・フィー率を更新するモーダルを開く |
| 対応記録を追加 | 対応履歴（電話／メール／面談／その他）を記録。次回アクション・次回期限も同時に更新できる |
| Lreach取込 | Lreachのヒアリングメモ（フリーテキスト）を貼り付けて自動解析し、顧客情報を上書き取込 |
| 編集 | 顧客情報（連絡先・現職／希望条件など）をまとめて編集 |
| 削除 | 顧客を削除（関連するタスク・面談・履歴も同時に削除。取り消し不可のため要注意） |

### パイプライン表示
画面上部に、以下12段階の主要ステータスを横並びで表示し、現在のステータスをハイライトします（一部の例外ステータスではこのバーは表示されません。詳細は「6. ステータス一覧」を参照）。

新規送客 → 初回連絡済み → 面談予約済み → 面談実施済み → 求人提案中 → 応募済み → 書類選考中 → 一次面接予定 → 最終面接予定 → 内定 → 承諾 → 入社済み

### 左側パネル（基本情報）
- 連絡先情報
- 現職・希望条件情報
- ヨミ情報
- 流入元・登録日など
- 次回アクション表示
- 備考

### 右側タブ
| タブ | 内容 |
|---|---|
| すべて | 対応履歴・タスク・面談を日付順にまとめたタイムライン |
| 活動履歴 | 対応履歴の一覧（インライン編集・削除・長文の展開表示） |
| タスク | 「＋タスクを追加」からタスク登録。チェックボックスで未完了⇔完了を切替 |
| 面談 | 面談の一覧表示（**閲覧のみ**。画面から面談を新規作成する機能はありません。面談はTimeRex連携で自動登録されます） |
| 提案求人 | この顧客に提案中の求人一覧と選考状況（詳細は「10. 求人提案」参照） |

### 推薦文
求人応募時に企業へ提出する推薦文をフリーテキストで記入・編集できます。

## 6. ステータス（顧客パイプライン）一覧

顧客ステータスは以下の23種類です。

新規送客／初回未対応／初回連絡済み／不通／面談予約済み／面談実施済み／面談キャンセル／リスケ調整中／求人提案中／応募意思確認中／応募済み／書類選考中／一次面接予定／一次面接結果待ち／最終面接予定／最終面接結果待ち／内定／承諾／入社予定／入社済み／辞退／失注／長期フォロー

- 新規登録時のデフォルトは「初回未対応」です。
- 上記のうち「不通」「リスケ調整中」「面談キャンセル」「応募意思確認中」「一次面接結果待ち」「最終面接結果待ち」「入社予定」「辞退」「失注」「長期フォロー」は、詳細画面上部のパイプラインバーには表示されない“例外ステータス”です。一時的な状態や終了状態として扱われます。
- ステータスを「面談予約済み」より後の段階（面談実施済み以降）に変更すると、その顧客の直近の面談レコードが自動的に「完了」扱いに同期されます。これはKPI集計を正しく行うための自動処理で、CAが面談レコードを個別に操作する必要はありません。

## 7. タスク管理（`/tasks`）

全顧客横断でタスクを一覧表示します。

### グルーピング
- 期限超過（赤）
- 本日期限（オレンジ）
- 今週（黄）

### 操作
- チェックボックスで未完了⇔完了を即時切替（完了時刻が自動記録されます）
- 優先度（高／中／低）バッジ表示
- 顧客名リンクから顧客詳細へ遷移可能

タスクは顧客詳細画面からも個別に追加・編集できます（担当CAとは別に「作業担当者」を設定可能です）。

## 8. 面談（Meeting）について

- 面談レコードは **CAが手動で作成することはできません**。すべてTimeRexの予約Webhookを通じて自動作成・更新されます（詳細は「15. TimeRex連携」参照）。
- 顧客詳細画面の「面談」タブでは、登録済みの面談を閲覧できるのみです。
- 顧客ステータスを面談実施後の段階に変更すると、直近の面談が自動的に「完了」に同期されます。

## 9. 求人管理（`/jobs`）

求人マスタの一覧画面です。

### 表示・絞り込み
- 検索（会社名／求人タイトル／エリア）
- ステータス絞り込み（募集中／停止／クローズ）
- 取込元バッジ（サーカス／ジョビンズ経由で自動取込した場合に表示）

### 求人の登録・編集
「求人を追加」または各行の編集アイコンから登録モーダルを開きます。

**手動入力項目**: 会社名（必須）、求人タイトル（必須）、ステータス、エリア、給与、雇用形態、フィー率、詳細、備考

**自動取込（スクレイピング）**:
求人ページのURLを貼り付けて「取込」ボタンを押すと、以下のサイトからは自動で項目を取得できます。
- サーカス（circus-job.com）
- ジョビンズ（jobins.jp）

取得に失敗した場合（Bot対策等でサーバー側から取得できない場合）は、「貼り付けて取込」欄が表示されます。求人ページをブラウザで開いた状態でデベロッパーツールのコンソールに `copy(document.documentElement.outerHTML)` を実行してHTMLをコピーし、その内容を貼り付けることで取込を行えます（画面上に手順の案内が表示されます）。

## 10. 求人提案（応募・選考管理）

顧客詳細画面の「提案求人」タブで管理します。

### 提案の追加方法
- **既存求人から提案**: ステータスが「募集中」かつ、まだこの顧客に提案していない求人から選択
- **新規求人を登録して提案**: その場で新規求人を登録し、同時にこの顧客への提案として追加

### 選考ステータス（提案ごとに管理、9段階）
提案 → 意思確認 → 応募 → 書類選考 → 面接 → 内定 → 承諾
（終了ステータスとして「辞退」「見送り」もあります）

各提案行のステータスはプルダウンからインライン変更できます。内定／承諾／辞退／見送りに変更すると決定日時が自動記録され、それ以外に戻すとクリアされます。

### 選択したコピー
提案一覧をチェックボックスで複数選択し、「選択をコピー」を押すと、`会社名` と `求人：URL` の形式でクリップボードにコピーされます。メールや外部チャットへの貼り付け用途に利用できます。

## 11. KPI画面（`/kpi`）

月を選択（前月／翌月ボタン、または月入力）すると、その月のCAごとの活動実績が表示されます（全CA分のカード＋「全体」サマリーカード）。

### 表示指標と算出ロジック

| 指標 | 内容 |
|---|---|
| 面談設定数 | 選択月内に面談日が設定された、キャンセルでない面談の件数（CA別） |
| 初回面談数 | 上記のうち実施済みと判定されたもの（結果入力あり、または面談・顧客ステータスが実施済み以降） |
| 求人提案数 | 「初回面談月」がその月である顧客のうち、求人提案を1件以上受けた**顧客数**（提案件数ではなく人数） |
| 選考数 | 同顧客群のうち、選考ステータス（応募／書類選考／面接／内定／承諾）に進んだ提案の件数 |
| 内定数 | 同顧客群のうち、内定または承諾に至った提案の件数 |
| 内定承諾数 | 同顧客群のうち、承諾に至った提案の件数 |

**重要な注意点**: 求人提案数以降の指標（求人提案数／選考数／内定数／内定承諾数）は、提案や選考が発生した月ではなく、**その顧客の初回面談があった月**に紐づけて集計されます。そのため、例えば6月に初回面談を行った候補者が8月に内定した場合でも、内定実績は6月のKPIとしてカウントされます。

### 表示される転換率
- 面談実施率 ＝ 初回面談数 ÷ 面談設定数
- 求人提案率 ＝ 求人提案数 ÷ 初回面談数
- 求人承諾率（表示ラベル、実態は「提案→選考」の転換率）＝ 選考数 ÷ 求人提案数
- 選考通過率 ＝ 内定数 ÷ 選考数
- 内定承諾率 ＝ 内定承諾数 ÷ 内定数

活動実績が0件のCAもカードは表示されます（0件として表示）。担当CA未設定のレコードは「未割当」として別集計されます。

## 12. ダッシュボード画面（`/dashboard`）

### KPIカード（CAで絞り込み可能）
- 総顧客数
- 初回未対応の件数
- 今週の面談数（キャンセルを除く）
- 期限切れタスクの件数

### 直近7日間のキャンセル
直近7日以内にキャンセルされた面談を一覧表示し、顧客詳細へのリンクを表示します。

### 月別ヨミ表
今後6ヶ月分＋データのある月＋「月未設定」の行に対して、ヨミランク（S/A/B/C/D／未設定）ごとの件数と合計、売上見込（万円単位）を表示します。
- 売上見込は `受注予定売上（万円）× フィー率（%）÷ 100` を対象顧客ごとに合計した金額です。
- 各行はクリックで対象顧客の内訳を展開表示できます。

### ステータス別・CA別集計
- ステータス別顧客数（棒グラフ、件数0のステータスは非表示）
- CA別担当件数（件数と全体に対する割合）

## 13. CSVインポート

顧客一覧画面の「CSVインポート」から、CSVファイルを一括で顧客登録できます。

### 対応する列名（日本語・英語どちらも可）
氏名／名前（name）、フリガナ、電話番号、メール、年齢、性別、居住地、現職企業、現職職種、現在年収、希望職種／希望勤務地／希望年収、転職希望時期、担当CA、流入元、ステータス、ヨミランク、受注予定月、備考、登録日

### 手順
1. CSVファイルを選択すると、内容が解析されプレビューが表示されます（最大50行まで表示。氏名が空欄の行は赤字で警告表示）。
2. 内容を確認し「確定」を押すと、実際に登録が実行されます。
3. 完了後、追加件数・スキップ件数の結果がアラート表示されます。
4. **重複判定**: メールアドレスまたは電話番号が既存顧客と一致する行は自動的にスキップされます（上書きはされません）。

## 14. Lreach連携（ブックマークレット）

Lreach（外部の紹介会社サイト）から求職者情報を取り込むための、ブラウザのブックマークレットが2種類用意されています。CAがLreachサイトを閲覧しながらワンクリックで実行します。

| ブックマークレット | 用途 |
|---|---|
| `lreach_bookmarklet.min.js` | Lreachの一覧画面から複数件の求職者情報をまとめて取込（`/api/ingest/lreach`） |
| `lreach_detail_bookmarklet.min.js` | Lreachの詳細画面（ヒアリングメモを含む）から1件を取込・更新（`/api/ingest/lreach-update`） |

- 導入方法は `bookmarklet/README.md` および同ディレクトリ内のスクリプトを参照してください。
- 一覧取込では、メール→電話番号→氏名の順で既存顧客とマッチングし、一致すればあくまで**空欄項目のみ**を補完します（既存の入力済みデータは上書きされません）。一致しない場合は新規顧客として登録され、流入元は自動的に「Lreach」、ステータスは「初回未対応」になります。
- 詳細取込では、一致した顧客に対して**送られてきた項目のみ**を上書き更新します。
- 顧客詳細画面の「Lreach取込」ボタンからヒアリングメモのテキストを直接貼り付けて取り込む方法もあります（ブックマークレットを使わない場合の代替手段）。

> 補足: `bookmarklet/README.md` には旧・Google Apps Script版Webアプリ（`lreachEndpoint.gs`）への接続方法が記載されていますが、現在配布されているブックマークレット本体は本CRM（`omoroi-crm.vercel.app`）に直接送信する設定になっています。README側の記述が古いままになっているため、参照する際はご注意ください。

## 15. TimeRex連携（面談予約の自動連携）

TimeRexで面談予約が確定・キャンセルされると、Webhook経由で本CRMに自動反映されます。CA側での操作は不要です。

- **予約確定時**: 顧客が存在しなければ新規作成（流入元「TimeRex」、ステータス「面談予約済み」）。既存顧客であればメール／氏名でマッチングし、面談レコードを作成・更新します。
- **キャンセル時**（主催者・ゲストいずれのキャンセルも対象）: 該当する面談のステータスが「キャンセル」に更新されます。

面談の新規作成・変更を手動で行うUIは存在しないため、予約日時などに誤りがある場合はTimeRex側の予約情報を確認・修正してください。

## 17. よくある質問／注意事項

**Q. 面談を手動で登録・修正したい**
A. 現状、面談はTimeRex連携でのみ作成されます。画面から新規作成・時刻修正はできません。予約内容の誤りはTimeRex側で修正してください。

**Q. CSVインポートで既存顧客を更新したい**
A. できません。メール／電話番号が一致する行は「スキップ」されるのみで、上書き更新はされません。既存顧客の情報修正は顧客詳細画面から個別に行ってください。

**Q. 担当CAを自分にすれば、自分の顧客だけしか見えなくなりますか？**
A. いいえ。担当CAはあくまで表示上の分類・フィルタ項目であり、アクセス制限はありません。ログインしているユーザーは全顧客・全求人・全タスクを閲覧・編集できます。

**Q. 顧客を削除すると何が消えますか？**
A. その顧客に紐づく対応履歴・タスク・面談もすべて削除されます。元に戻せないため、削除前によく確認してください。

**Q. ヨミ（受注予定売上）はどこで見られますか？**
A. ダッシュボード画面の「月別ヨミ表」で、ヨミランク別・月別に件数と売上見込を確認できます。個別の設定は顧客詳細画面の「ヨミ更新」ボタンから行います。

**Q. リポジトリにある `.gs` ファイルやスプレッドシートは今も使いますか？**
A. 使いません。これらは移行前の旧システムの名残です。現在は本CRM（`crm-app`）のみが正となる業務システムです。
